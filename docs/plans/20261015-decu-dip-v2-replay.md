# Decu-dip v2 historical paper replay — milestone 4

Status: Draft for approval — new strategy `decu-dip` v2 (own config, engine, results), a first-ever evidence gate, execution with quote-relative slippage and an exit retry ladder, and a one-position portfolio replay over several case datasets. Waiting on the "Assumptions to confirm" below.

Milestone 4 of the approved [capture, paper and chart improvement plan](20261011-capture-paper-chart-improvement-plan.md) (work unit 5 of section 10; sections 2, 7 and 10 apply). The single source of truth for the rules is the [decu-dip v2 spec](../strategy/decu-dip-v2-spec.md); where code and spec disagree the spec wins. This plan only translates the spec to historical replay and says where replay cannot know the answer. Milestones 1 and 2 are inputs (case datasets and wallet captures).

Out of scope: live trading, signing, sending, the live ownership log and streams (spec 3A live), catch-up and gap-fetch RPC logic, Telegram alerts (their replay equivalents are `SKIP_UNVERIFIED` and `UNRESOLVED`), PumpSwap/AMM execution (spec section 10: migration is a coverage gap), chart work, and any frontend code (Codex gets a brief).

## Decisions

- **A new strategy beside the old one.** `decu-dip` version `2`, config `DecuDipConfig` mirroring the spec YAML (bps, ms, SOL decimals, `exitRetry`, `recordingWindowMs`), engine id `decu-dip-replay-v1`. `DipEntryStrategy`, `SimulationConfig` (`dip-entry` v1), `ReplayRunner` (`dip-paper-v2`), `FillModel`, `PositionService`, `ConsoleConfigValidator` and the legacy hash list are not edited; their run ids, result checksums and stored runs stay byte-identical. The selector is additive: `RunStartRequest.strategy` defaults to `dip-entry`; a request without it behaves exactly as today.
- **One price measure.** Post-trade price = `BondingCurve.spotPrice(observation.curve.reserves)` (virtual SOL / virtual token, SOL per token). The legacy `MarketObservation.price` (trade amount ratio) is never a trigger. Reference = post-trade spot of the signal's own trade, read from the signal transaction's decoded `PumpFunBuyFacts.postReserves` (case windows start at S+1, so the signal trade is not an observation).
- **Signal checks in spec order (section 4).** (1) accepted BUY by the tracked wallet; (2) SOL spent on tokens > 1.9 strictly, else `SKIP_SIZE`; (3) first-ever, else `SKIP_NOT_FIRST` / `SKIP_UNVERIFIED`; (4) reference mcap = reference price × 1,000,000,000 (`PumpFunLayout.TOKEN_SUPPLY`) × SOL/USDT at t0's UTC minute, > 10,000 strictly, else `SKIP_MCAP`; (5) slot free, else `SKIP_POSITION_OPEN`. Rates are USDT, labelled "USD proxy" in every result. A missing t0 block time or rate is `SKIP_UNVERIFIED` with a detail code, never a guess.
- **Dip watch.** Entry level = reference × 0.80 (scale 38). Watched: eligible (`ObservationEligibility`) observations in slots after S; `curveComplete` ends the watch. The first observation with post-trade price ≤ level is the dip. Submission time = dip block time + `latency.submissionLatencyMs`; it counts iff ≤ t0 + 30,000 ms (30.000 s counts, 30.001 s is `SKIP_NO_DIP`). A dip whose submission would be late is not retried on a later trade.
- **"Backfilled never trigger", for replay.** All data is historical and treated as a live stream delivered at block time + latency, in slot order. Only slots after the signal's slot are watched. Slot S itself is unobserved by the existing window and reported as coverage gap `SAME_SLOT_UNOBSERVED`.
- **Simulated latency is explicit and labelled.** `SimulatedLatency { submissionLatencyMs, landingSlots, confirmationLatencyMs }` is part of the config, its hash and every report ("ASSUMPTION: simulated, not measured"). Submission slot = trigger slot + ceil(submissionLatencyMs / 400) (named slot-time constant). An attempt lands on the first eligible observation with slot ≥ submission slot + `landingSlots` before curve completion, against that observation's post-trade curve (bonding-curve-execution convention). Block times are whole seconds; ms arithmetic only adds configured latency. Confirmation received = landing block time + `confirmationLatencyMs`. Time-triggered attempts use the slot of the last observation with block time ≤ their send time as submission slot.
- **Entry execution (section 7).** Size 0.1 SOL (basis: assumption 4); quote = tokens for the size against the latest post-trade reserves at or before the submission slot; price limit = quote average price (incl. protocol and creator fees) × 1.15, enforced as the equivalent minimum-tokens test in exact integer arithmetic against the landing curve. One attempt. Priority fee 0.001 plus configured network fee (default 0.000005). Outcomes: confirmed → `OPEN`; limit breached → `ENTRY_FAILED_SLIPPAGE`; `EXCEEDS_CURVE` or zero tokens → `ENTRY_FAILED_OTHER`; no landing trade within 150 slots while data continues → `ENTRY_EXPIRED` (no fee); data ends first → `ENTRY_UNKNOWN`, coverage `INCOMPLETE` (slot kept). `ENTRY_SEND_ERROR` cannot arise from history; it exists in the enum and only a test fault hook produces it.
- **Average fill and levels.** Average fill = (curve payment + protocol + creator fee) / tokens, excluding network and priority fees (spec section 5). TP = fill × 1.55, SL = fill × 0.60 (scale 38). Triggers are post-trade spot prices of eligible observations after the landing slot, from confirmation time on (detection = block time + `submissionLatencyMs`).
- **Exit (section 8).** `exit_start = min(confirmation + 180 s, t0 + 240 s)`. First trigger by detection time wins and fixes the reason (`TAKE_PROFIT`, `STOP_LOSS`, `TIME_EXIT`). Ladder from `exitRetry`: attempt k sent at start + 3 s × k, slippage steps [1500 ×3, 2500 ×3, 4000…], priority 0.001 × 1.5^k capped at 0.003. Each attempt sells the whole balance into its landing curve with min-out `quote / (1 + slippage)`. A landed attempt that misses its limit (or hits a curve that cannot pay) fails and pays fees; the next attempt is still sent. An attempt sent before an earlier winner is confirmed lands as a zero-balance failure and pays. Active phase 60 s or paid fees ≥ 0.02 SOL, then `UNRESOLVED`; retries continue every 30 s at 40% and 0.002 until the dataset ends. A late sale keeps the original reason with `resolvedLate = true`.
- **Dataset ends before resolution.** Case windows are 4500 slots (~30 min) from S, covering t0 + 4 min plus the active phase. A position unsold when observations end, or at a `curveComplete` trade, is `UNRESOLVED` with coverage `INCOMPLETE` and a gap range. A skip or failed entry decided on missing data keeps its code, carries `INCOMPLETE` and is excluded from judged totals (listed separately). Never a synthetic exit.
- **Fees and PnL.** Per cash flow: curve payment, pump fees, priority fee, network fee. Net PnL (SOL) = proceeds − cost basis − all fees of landed transactions (failed ones included). USD = each cash flow at the dataset rate of its own landing minute (USDT proxy). Token-account rent not charged (refunded on close, as in the execution ADR). Skips without a landed transaction have PnL 0.
- **First-ever, for replay (spec section 3).** History = the tracked wallet's complete WALLET_REFERENCES listing from the token's creation slot up to the signal; any successful transaction before the signal slot that touches the mint (mint among account keys or in pre/post token balances) → `SKIP_NOT_FIRST`; plus check C on the signal's `preTokenBalances`. User decision: any earlier interaction disqualifies; unknown or incomplete history → `SKIP_UNVERIFIED`, never a pass by absence of evidence. Positive NOT_FIRST evidence wins over incomplete coverage; otherwise any gap is UNVERIFIED. Failed transactions change nothing. Other transactions in the signal's own slot that touch the mint → UNVERIFIED (within-slot order unrecorded; same convention as `SAME_SLOT_BUY`).
- **Where first-ever evidence comes from:**

| Need | Existing evidence | Gap |
|---|---|---|
| Creation slot, signature, time | Wallet+token manifest v4 creation search (`ActualFirstBuyRule.creation()` → `CreationOutcome.Identified`, or B's own artifact when it runs `create`/`create_v2`) | Only for wallet+token cases whose step 1 found B; absent from v3 datasets and market manifests. Needs the identified creation, not `Proven`. No creation → UNVERIFIED |
| Wallet listing completeness | WALLET_REFERENCES manifest: `discoveryStop`, `selection`, artifacts for FAILED/NON_SIGNER/UNCLASSIFIED | New predicate: HISTORY_END, or oldest selected slot < creation slot. Any record in [creation, signal] without an artifact (UNAVAILABLE, UNSUPPORTED_VERSION, WITHHELD_UNSAFE_TEXT, PENDING, PROVIDER_UNAVAILABLE) → UNVERIFIED |
| Transfers, sells, third-party account creation | Wallet-signed and non-signer artifacts are stored | `ActualFirstBuy.Proven` proves only "no earlier curve buy"; `TargetTokenAssessment` ignores NON_SIGNER. The new rule reads every listed artifact |
| Check C and signal facts | Signal artifact; `PumpFunBuyDecoder` → `PumpFunBuyFacts` | `WalletTokenBalances.owned` is private; a pre-existing-account reader is new |

- **Portfolio replay (section 9, P13).** Each candidate passing checks 1–4 gets a solo trajectory (acquire = dip trigger detection; release = final entry failure, `CLOSED` or late resolution); our trades do not move the market. A scheduler walks candidates by (acquire instant, t0, slot, signature), accepting one only when no accepted interval covers its acquire instant. A signal whose t0 falls inside an accepted interval is `SKIP_POSITION_OPEN` at check 5; one losing at acquire time is `SKIP_POSITION_OPEN` at acquisition; both record `skipPoint`. `UNRESOLVED` and `ENTRY_UNKNOWN` hold the slot to the end of the run; later skips are flagged `blockedByUnresolved`.
- **Run input.** `DecuDipRunInput`: a set of case datasets (each a v3/v4 `ReplayDataset` plus its evidence), sorted by checksum, duplicates collapsed, observations merged by id with the existing conflict check, one tracked wallet. A single-dataset run is the one-element case. `inputChecksum = StableHash(sorted [datasetChecksum, evidenceChecksum])`; `runId = StableHash(engine, inputChecksum, configHash)`; `configHash` covers every `DecuDipConfig` field, latency, supply, scale, rounding and rule texts. The `simulation_runs` unique key is unchanged and holds `inputChecksum` in `dataset_checksum`. Changed evidence is a new run. A dataset without evidence replays with its signals `SKIP_UNVERIFIED`.
- **Persistence is additive.** One `simulation_runs` row per run (scenario = signals, filled = confirmed entries, rejected = skips and failed entries, open = `UNRESOLVED`, closed, realized PnL in SOL; snapshots hold config, input manifest and report JSON) plus new tables for signals, exit attempts, run inputs and case evidence. Legacy intent/order/position tables are not used.

## Acceptance checks

Fixtures mirror the spec. Prices are SOL per token with supply 1e9 and rate 200 USDT/SOL, so section 13's USD figures map to SOL (reference $20,000 = 1.0e-7).
- **Section 3 table** (wallet-capture fixtures): never touched, buys 2.5 SOL → signal. First buy 1 SOL then 3 SOL → `SKIP_SIZE`, then `SKIP_NOT_FIRST`. Received by transfer, sent away, buys 3 → `SKIP_NOT_FIRST`. Bought, sold all, buys 3 → `SKIP_NOT_FIRST`. Third-party airdrop that created his account (NON_SIGNER artifact) or into an existing account (check C) → `SKIP_NOT_FIRST`. Listing stopping above the creation slot, missing creation, or a record without an artifact → `SKIP_UNVERIFIED`. No evidence at all → `SKIP_UNVERIFIED`.
- **Size and mcap:** exactly 1.9 SOL → `SKIP_SIZE`; 1.9 SOL plus one lamport passes. Reference mcap exactly $10,000 → `SKIP_MCAP`; $12,000 passes though the entry level is $9,600.
- **Worked example (section 13):** level 8.0e-8, dip post-trade 7.95e-8 at 12 s, submission latency 600 ms, quote ≈ 8.025e-8, limit ≈ 9.23e-8, landing at 13 s + 400 ms confirmation = 13.4 s, TP ≈ 1.249e-7, SL ≈ 4.84e-8, `exit_start` 193.4 s after t0, price 1.255e-7 at 110 s → `TAKE_PROFIT`, attempt 1 lands, closed. Expected raw-unit values hand-computed independently of the engine.
- **Dip window:** dip at t0 + 30 s with latency 0 → entered; latency 1 ms → `SKIP_NO_DIP`; dip at t0 + 31 s → `SKIP_NO_DIP`; a dip at 12 s that lands after 30 s still counts.
- **Slippage:** landing 20% worse than quote → `ENTRY_FAILED_SLIPPAGE`, fees paid, slot released; 14.9% worse fills; `EXCEEDS_CURVE` → `ENTRY_FAILED_OTHER`; no landing in 150 slots → `ENTRY_EXPIRED`, no fee; dataset ends first → `ENTRY_UNKNOWN`, `INCOMPLETE`.
- **Exits:** TP crossing before SL → `TAKE_PROFIT`, and the reverse; a crossing after `exit_start` is ignored (`TIME_EXIT`); late confirmation makes t0 + 4 min win.
- **Ladder fee accounting:** attempts 1–3 fail on slippage, attempt 4 sells; paid fees = priority 0.001 + 0.0015 + 0.00225 (+ network each) plus the winner's; a pre-winner attempt lands as a zero-balance failure and pays; the 0.02 SOL cap ends the active phase early; all attempts fail → `UNRESOLVED`, new signals `SKIP_POSITION_OPEN`; a sale in the 30 s retries → original reason, `resolvedLate = true`, slot released then.
- **Dataset end:** observations end unsold → `UNRESOLVED`, `INCOMPLETE`, gap range, no exit fill; a `curveComplete` trade does the same; a watch meeting `curveComplete` → `SKIP_NO_DIP` with a migration gap.
- **Portfolio:** two tokens dipping at the same instant → lower (t0, slot, signature) trades, the other `SKIP_POSITION_OPEN` at acquire; a signal whose t0 falls inside an open position → `SKIP_POSITION_OPEN` at check 5; two datasets interleave chronologically regardless of request order; a single-dataset run equals the same dataset inside a larger non-overlapping set.
- **Determinism and legacy:** same input twice → same `runId`, result checksum and stored run (idempotent, concurrent writers converge); changed evidence or latency → new run; `dip-sample-v3` keeps its pinned `runId`, `configurationHash` and `resultChecksum`; all existing dip-entry tests pass unchanged.

## Schema and compatibility

Only new tables: `decu_dip_case_evidence`, `decu_dip_run_inputs`, `decu_dip_signals`, `decu_dip_exit_attempts` (indexed by run id; unique per run on signal signature and instruction). Hibernate `update` creates them locally and in tests; production needs `docs/schema/V20261015130000__decu_dip_replay.sql` applied by hand first, including its CHECK constraints. `simulation_runs`, its unique key and all existing tables are unchanged. Dataset bytes and checksums, manifests and the legacy API default are unchanged; the evidence sidecar is a separate versioned format (`decu-dip-case-evidence/v1`). API additions are optional fields. Window length is unchanged (4500 slots); a shorter capture is reported `INCOMPLETE`, not extended.

## Assumptions to confirm

1. **Signal size basis.** "SOL spent on tokens" for the > 1.9 test = curve payment plus protocol and creator fee (the spec excludes only network fee, priority fee, tips and rent). A 1.88 SOL curve payment with a 1.25% fee is 1.9035 SOL and passes under this reading; under curve-payment-only (`WalletTransaction.quoteDelta`) it fails.
2. **Default simulated latency.** `submissionLatencyMs` 600, `landingSlots` 1, `confirmationLatencyMs` 400, network fee 0.000005 SOL, from the spec section 13 timeline, not measured. Results shown beside 0 ms and 2000 ms sensitivity runs.
3. **Failed but landed attempts pay fees.** Landed failed entries and exit attempts pay priority and network fee; expired attempts pay nothing.
4. **Position size basis.** 0.1 SOL is the curve payment with fees on top (existing `FillModel` convention; swap input ≈ 0.1013 SOL). Alternative: 0.1 SOL is the total swap input including protocol fee.
5. **Unresolved holds the slot.** An `UNRESOLVED` or `ENTRY_UNKNOWN` position at dataset end holds the slot for the rest of the run (spec: stop all entries); later signals are `SKIP_POSITION_OPEN` flagged `blockedByUnresolved`.
